Core API

Embeddings

createEmbedder() turns text, images and audio into vectors on the device — semantic search, RAG retrieval, deduplication, clustering and classification, with no server in the loop. It runs beside an LLM, or on its own.

Quick start

Load an EmbeddingGemma 2 bundle, embed what you search with EmbeddingTask.document and the query with EmbeddingTask.searchQuery, then rank with topK:

typescript
import { createEmbedder, EmbeddingTask, topK, EMBEDDING_GEMMA_2_TEXT_270M } from "react-native-litert-lm";

const embedder = createEmbedder();
await embedder.loadModel(EMBEDDING_GEMMA_2_TEXT_270M, { maxInputLength: 256 });

const options = { normalize: true, outputSize: 256 } as const; // Matryoshka: 768 → 256 dimensions
const index = await embedder.embedBatch(notes.map(EmbeddingTask.document), options);
const query = await embedder.embed(EmbeddingTask.searchQuery("when is my flight?"), options);
const best = topK(query, index, 3); // [{ index, score }], best first
  • Prompts matter. EmbeddingGemma 2 was trained with task prompts, and EmbeddingTask builds them for you.
  • Vectors are Float32Arrays over native memory, with no JSON on the way. The vector helpers work on them in plain JS, which is plenty for the thousands of vectors an on-device index holds.
  • outputSize truncates to 512, 256 or 128 dimensions, and the engine re-normalizes after truncating — see Matryoshka output sizes.
  • maxInputLength picks the smallest compiled input that fits (128–8192 tokens): less memory, faster calls.

Embedding models

EmbeddingGemma 2 is the embedding family the engine supports. Both bundles are public on the Hugging Face Hub — no account or authentication required — and produce 768-dimension vectors:

ConstantInputsSizeMin RAM
EMBEDDING_GEMMA_2_TEXT_270M Text — 100+ languages and code 165 MB 2 GB+
EMBEDDING_GEMMA_2_740M Text, images and audio, in one space 485 MB 3 GB+

Both models were verified end to end on the iOS simulator and an Android emulator for this release, and both fit on iOS without the Extended Virtual Addressing entitlement. Per-SoC NPU variants of the 740M model live in the same repository; with backend left unset, a per-SoC NPU build runs on its NPU.

One model type per factory

Embedding bundles load with createEmbedder(), LLMs with createLLM(). The bundle says which it is, so the wrong pairing rejects with MODEL_TYPE_MISMATCH before any weights load — see Know the model before loading it.

createEmbedder()

function createEmbedder(): EmbedderInstance

Creates an embedding model — LiteRT-LM's EmbeddingEngine. It is a separate engine from createLLM(), with its own serial queue (iOS) or worker thread (Android), so an embedder and a loaded LLM can work at the same time.

EmbedderInstance

export interface EmbedderInstance { loadModel( pathOrUrl: string, config?: EmbedderConfig, onDownloadProgress?: (progress: number) => void, ): Promise<void>; embed(input: EmbeddingInput, options?: EmbeddingOptions): Promise<Float32Array>; embedBatch(inputs: EmbeddingInput[], options?: EmbeddingOptions): Promise<Float32Array[]>; getModelInfo(): ModelInfo | null; isReady(): boolean; getMemoryUsage(): MemoryUsage; unload(): Promise<void>; close(): void; } /** Text, or the same multimodal parts execute() takes. */ export type EmbeddingInput = string | MultimodalPart[];
MethodDescription
loadModel(pathOrUrl, config?, onDownloadProgress?) Download (for an HTTPS URL, reporting 0–1 progress) and load an embedding bundle, after the same pre-flight checks as createLLM().loadModel() — see Loading.
embed(input, options?) One vector for one input: a string, or MultimodalParts. The Float32Array views native memory — no copy, no JSON. Apply an EmbeddingTask prompt to text first.
embedBatch(inputs, options?) One vector per input, computed in a single engine call. An empty array resolves to [].
getModelInfo() What the loaded bundle declares — dimension, input lengths, modalities (ModelInfo). null before a load, or when the bundle's metadata could not be read.
isReady() Whether a model is loaded.
getMemoryUsage() Real memory usage from the OS — the same MemoryUsage an LLM instance reports.
unload() Free the engine; the instance can load again.
close() Free the engine for good. It returns at once and frees the engine after any in-flight call.

As with execute(), a leading file:// is stripped from part paths, so URIs from image pickers work as-is.

Loading

loadModel() resolves the path through ModelRegistry — an HTTPS URL downloads once, then comes from the cache — and reads the bundle's metadata to check it before any weights load:

  • An LLM bundle rejects with MODEL_TYPE_MISMATCH.
  • A bundle that needs a newer engine rejects with RUNTIME_TOO_OLD.
  • With backend omitted, the bundle's preferred backend that this device can run is used, so a per-SoC NPU build runs on its NPU. A bundle this device can't run at all rejects with UNSUPPORTED.
  • maxInputLength above the encoder's longest compiled input is capped to it, with a console note.
  • Memory gets the same pre-flight estimate as an LLM, with the input length (maxInputLength, 512 when unset) standing in for the context. A 'critical' verdict throws a MemoryError instead of loading; forceLoad: true skips the check.

A bundle whose metadata can't be read loads without the bundle checks, with a warning, and the engine has the final say.

EmbedderConfig

Load-time settings, passed to loadModel() or as the second argument to useEmbedder(). All fields are optional.

FieldTypeDefaultDescription
backend Backend the bundle's preference, else 'cpu' Backend for the text encoder.
visionBackend Backend the bundle's Backend for the image encoder. Unset: the backend the bundle declares, or no image encoder when it declares none.
audioBackend Backend the bundle's Backend for the audio encoder. Unset: the backend the bundle declares, or no audio encoder when it declares none.
maxInputLength number — Longest input, in tokens, the encoder is prepared for. Picks the smallest compiled signature that fits (EmbeddingGemma 2: 128–8192), so a smaller value means less memory and faster calls. The compiled lengths are in getModelInfo().embedding.inputLengthOptions.
visionTokensPerImage number — Visual tokens per image (EmbeddingGemma 2: 70 or 140).
activationDataType ActivationDataType — Activation precision; support depends on model and backend.
forceLoad boolean false Skip the pre-flight memory check (like LLMConfig.forceLoad).

EmbeddingOptions

Per-call settings for embed() and embedBatch().

FieldTypeDefaultDescription
normalize boolean — Return a unit-length vector, so dot product equals cosine similarity.
outputSize number full width Matryoshka truncation: keep only the first N dimensions (EmbeddingGemma 2: 128, 256, 512 or 768). Smaller vectors cost less to store and compare.
insertSpecialTokens boolean engine default Add the model's special tokens around text input.
visionTokensPerImage number — Visual tokens for images in this call.

Task prompts: EmbeddingTask

EmbeddingGemma 2 was trained with task prompts, so send them. EmbeddingTask builds the prompts from its model card. Each builder trims its input and takes one argument, so it can be passed straight to Array.map — notes.map(EmbeddingTask.document).

// EmbeddingTask.<builder>(input) returns the text to embed: searchQuery(query) // task: search result | query: … document(doc) // title: … | text: … questionAnswering(question) // task: question answering | query: … factChecking(claim) // task: fact checking | query: … codeRetrieval(query) // task: code retrieval | query: … classification(text) // task: classification | query: … clustering(text) // task: clustering | query: … sentenceSimilarity(text) // task: sentence similarity | query: …
BuilderUse it for
searchQuery(query) The query side of search.
document(doc) Every corpus item, for any retrieval task. Takes a string, or { title, text } when the item has a real title (a heading, subject line or file name); a missing title is written as none, as the model expects.
questionAnswering(question) The question; passages use document.
factChecking(claim) The claim; evidence uses document.
codeRetrieval(query) The query side of code search; code uses document with the file name as its title.
classification(text) Every input to a classifier built on the embeddings.
clustering(text) Every input to clustering.
sentenceSimilarity(text) Both sides of a similarity comparison.

Which prompt goes where depends on the task:

  • Retrieval is asymmetric. The query gets its task prompt (searchQuery, questionAnswering, factChecking, codeRetrieval), and every corpus item gets document.
  • Classification, clustering and similarity are symmetric. Every input being compared gets the same prompt.
  • Images and audio take no prompt. Pass them as parts — see Images and audio.
typescript
// Titled corpus items: the title is part of what the model reads
const docs = await embedder.embedBatch(
  articles.map((a) => EmbeddingTask.document({ title: a.heading, text: a.body })),
  options,
);

// Symmetric tasks: the same prompt on both sides
const [a, b] = await embedder.embedBatch(
  [EmbeddingTask.sentenceSimilarity(first), EmbeddingTask.sentenceSimilarity(second)],
  options,
);
The model card wins

LiteRT-LM's embedding page shows an older task: search query | text: form. These builders follow the prompts EmbeddingGemma 2 was trained and benchmarked with, from its model card.

Vectors and similarity

embed() resolves with a Float32Array over native memory. The helpers below work on any ArrayLike<number> in plain JS. They are pure, and they are also importable from react-native-litert-lm/core for Node scripts and tests.

function cosineSimilarity(a: ArrayLike<number>, b: ArrayLike<number>): number function dotProduct(a: ArrayLike<number>, b: ArrayLike<number>): number function normalize(v: ArrayLike<number>): Float32Array function topK( query: ArrayLike<number>, candidates: ReadonlyArray<ArrayLike<number>>, k: number, ): EmbeddingMatch[] /** One ranked hit from topK. */ interface EmbeddingMatch { /** Index into the `candidates` array */ index: number; /** Cosine similarity to the query */ score: number; }
HelperReturns
cosineSimilarity(a, b)Cosine similarity in [-1, 1]. Returns 0 if either vector is all zeros.
dotProduct(a, b)The dot product. Equals cosine similarity when both vectors are unit length (normalize: true).
normalize(v)A unit-length copy of v (all-zero input returns zeros). The only helper that copies.
topK(query, candidates, k)The k candidates most similar to query, best first, as { index, score }. A linear scan — plenty for the thousands of vectors an on-device index typically holds.
Same model, same size

Vectors of different lengths throw a RangeError (Embedding dimensions differ (… vs …)). Compare only vectors produced with the same model and the same outputSize.

Matryoshka output sizes

EmbeddingGemma 2 vectors are 768 dimensions wide, trained so that their leading dimensions still work as an embedding on their own. outputSize keeps the first 512, 256 or 128 — close to lossless down to 256 — and the engine re-normalizes after truncating. Smaller vectors cost less to store and compare: at 256 dimensions an index takes a third of the space.

typescript
// Index and queries must share one outputSize
const options = { normalize: true, outputSize: 256 } as const;

const index = await embedder.embedBatch(notes.map(EmbeddingTask.document), options);
const query = await embedder.embed(EmbeddingTask.searchQuery(input), options);
topK(query, index, 5); // 256-dimension vectors on both sides

Changing outputSize later means re-embedding the index: a 256-dimension query can't be compared with 768-dimension documents.

Input length

The encoder is compiled for a set of input lengths. maxInputLength picks the smallest one that fits — less memory, faster calls — so set it to the longest input you expect rather than the model's maximum. The loaded bundle lists its options:

typescript
await embedder.loadModel(EMBEDDING_GEMMA_2_TEXT_270M, { maxInputLength: 256 });

const info = embedder.getModelInfo();
info?.embedding?.dimension;          // output width before any outputSize truncation
info?.embedding?.inputLengthOptions; // the input lengths the encoder was compiled for

Images and audio

EMBEDDING_GEMMA_2_740M embeds images and audio into the same space as text, so a text query can find a photo or a recording. Images and audio take no prompt: pass them as the same MultimodalParts execute() takes, by path or as a buffer.

typescript
import { createEmbedder, EmbeddingTask, topK, EMBEDDING_GEMMA_2_740M } from "react-native-litert-lm";

const embedder = createEmbedder();
await embedder.loadModel(EMBEDDING_GEMMA_2_740M);

const options = { normalize: true } as const;
const photos = await embedder.embedBatch(
  photoPaths.map((path) => [{ type: "image" as const, path }]),
  options,
);
const query = await embedder.embed(EmbeddingTask.searchQuery("a dog on a beach"), options);
const matches = topK(query, photos, 5);

Images and audio need the 740M model; the 270M bundle is text-only. visionTokensPerImage (70 or 140 for EmbeddingGemma 2) sets how many visual tokens an image gets, at load time or per call.

useEmbedder

function useEmbedder( pathOrUrl: string, config?: UseEmbedderConfig, ): UseEmbedderResult

The embedding counterpart of useModel: it manages download, pre-flight, load and cleanup. UseEmbedderConfig extends EmbedderConfig with one field of its own, autoLoad (default true): load as soon as the hook mounts.

FieldTypeMeaning
embedder EmbedderInstance | null The underlying instance. null until created.
isReady boolean True once the model is loaded.
downloadProgress number Download progress as a 0–1 fraction.
error string | null The last load error message, or null.
errorCode LiteRTLMErrorCode | null Typed code of the last load failure, e.g. 'MODEL_TYPE_MISMATCH'.
modelInfo ModelInfo | null What the loaded bundle declares: dimension, input lengths, modalities. null until loaded.
embed (input, options?) => Promise<Float32Array> One vector for one input. Rejects with MODEL_NOT_LOADED until the model is ready.
embedBatch (inputs, options?) => Promise<Float32Array[]> One vector per input, in one engine call. Rejects with MODEL_NOT_LOADED until the model is ready.
load () => Promise<void> Download (if needed) and load the model — for autoLoad: false, or to retry after an error.
  • Create on mount, close on unmount. The hook creates the embedder when it mounts and closes it when the component unmounts.
  • Reloads follow the inputs. With autoLoad on, it loads on mount and again when pathOrUrl or a config value changes. The config is destructured into primitives, so an inline object literal does not cause reload loops.
  • Load failures land in state. error and errorCode describe a failed load; a failed embed() rejects with a typed error for you to catch.
useNoteSearch.ts
import { useEffect, useState } from "react";
import { EMBEDDING_GEMMA_2_TEXT_270M, EmbeddingTask, topK, useEmbedder } from "react-native-litert-lm";

const NOTES = [
  "Dentist appointment moved to Thursday at 3pm.",
  "Flight to Tokyo departs SFO on May 4, seat 32A.",
  // …
];
const OPTIONS = { normalize: true, outputSize: 256 } as const;

function useNoteSearch() {
  const { isReady, embed, embedBatch } = useEmbedder(EMBEDDING_GEMMA_2_TEXT_270M, {
    maxInputLength: 256,
  });
  const [index, setIndex] = useState<Float32Array[] | null>(null);

  // Embed the notes once, as soon as the model is ready (the document side of search)
  useEffect(() => {
    if (!isReady || index) return;
    embedBatch(NOTES.map(EmbeddingTask.document), OPTIONS).then(setIndex, console.warn);
  }, [isReady, index, embedBatch]);

  return async (query: string) => {
    if (!index) return [];
    const vector = await embed(EmbeddingTask.searchQuery(query), OPTIONS);
    return topK(vector, index, 3).map(({ index: i, score }) => ({ note: NOTES[i], score }));
  };
}

Example app: Search notes

The example app's Search notes sheet (example/src/components/SearchPanel.tsx) is a working semantic search over a dozen notes. It loads EMBEDDING_GEMMA_2_TEXT_270M on demand (autoLoad: false, maxInputLength: 256), embeds the notes once in a single embedBatch() call with EmbeddingTask.document, embeds each query with EmbeddingTask.searchQuery on submit, and ranks the notes with topK — vectors truncated to 256 of 768 dimensions. Try “teeth cleaning” or “what do I need for the garden?”: the notes match by meaning, not keywords.

Errors

Failures are LiteRTLMErrors with a stable code: MODEL_TYPE_MISMATCH, RUNTIME_TOO_OLD and UNSUPPORTED from the bundle checks, MEMORY_ESTIMATE_EXCEEDED from the memory pre-flight, INVALID_INPUT for a bad part (a missing media file, an unreadable buffer), and EMBEDDING_FAILED when the engine fails a call. useEmbedder() exposes a failed load's code as errorCode.
