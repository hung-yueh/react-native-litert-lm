Models & registry

Which bundles run, the bundled model URL constants, how to know a model before loading it, the Models identifier map, and ModelRegistry — the single source of truth for model download and cache state.

Supported models

Any .litertlm bundle runs if the engine knows its model family: Gemma 4, 3n and 3, FunctionGemma, Qwen 3 and 3.5, LFM2, MiniCPM, FastVLM and generic decoders, plus EmbeddingGemma 2 for embeddings. litert-community hosts hundreds of them. This is a native inference engine, not a Python runtime — raw Hugging Face checkpoints will not load.

inspectModel() tells you what a bundle is before you load it, and manifest resolution picks a repo's right variant for the device.

Verified for this release

Gemma 4 E2B, LFM2.5 and both EmbeddingGemma 2 models were verified end to end on the iOS simulator and an Android emulator for this release. The embedding models are covered on Embeddings.

LFM2.5

LFM2.5 is under the LFM Open License, not Apache; check its commercial terms. It runs on CPU: the Metal GPU engine fails for this model family on iOS, and on Android resolveFromManifest("litert-community/LFM2.5-1.2B-Instruct") picks the GPU re-export where it helps. Its tool calls use LFM's own <|tool_call_start|> syntax, which parseToolCalls() doesn't read.

Prefer Gemma 4

GEMMA_3N_E2B_IT_INT4 is deprecated. GEMMA_4_E2B_IT is smaller (2.58 GB), adds audio, tool calling and thinking, and is served straight from the Hub. Gemma 3n is mirrored on models.litert.dev only because the upstream repo google/gemma-3n-E2B-it-litert-lm is gated — it returns 401 without an access token and manual license approval. The constant still works, and the former litert.dev/… URL redirects to the mirror, so shipped apps are unaffected.

iOS entitlement

Models over ~2 GB need the Extended Virtual Addressing entitlement on iOS — that includes the Gemma 4 and Gemma 3n models above. Without it, iOS caps virtual memory and kills the app during load. LFM2.5 and the embedding models fit without it.

Gemma 4 capabilities

Gemma 4

Gemma 4 models support thinking mode (reasoning content arrives in <thinking>…</thinking> markers), tool calling (<tool_call>…</tool_call> markers, answered with tool results), audio input, and are NPU-optimized. Gemma 4 E2B also ships a speculative-decoding drafter. The library parses the channel markers into typed events — see Inference & streaming.

Know the model before loading it

A .litertlm bundle describes itself. inspectModel() reads that description without loading the weights, in milliseconds rather than the seconds and gigabytes a load costs:

typescript
import { inspectModel, recommendBackend, getDeviceInfo } from "react-native-litert-lm";

const info = await inspectModel(path); // a local path, or a URL that is already downloaded
info.type;              // 'llm' | 'embedding' | 'unknown'
info.modalities;        // { text, vision, audio, video }
info.maxContextTokens;  // the bundle's limit
info.backends.text;     // backends it was built for, most preferred first
recommendBackend(info); // { backend, reason, candidates } for this device
getDeviceInfo();        // platform, SoC, memory, GPU availability

loadModel() runs the same checks for you — see the load pre-flight — so most apps never call these directly. They earn their keep in model pickers and settings screens.

inspectModel(pathOrUrl)

function inspectModel(pathOrUrl: string): Promise<ModelInfo>

Reads a bundle's metadata — model type, input modalities, context limit, declared backends, NPU target, sampler defaults, minimum runtime — without creating an engine. It accepts a local path, a file:// URI, or the URL of a model that is already downloaded. It never downloads: a URL that isn't cached rejects with MODEL_NOT_FOUND, so call ModelRegistry.resolveModel() first.

Note

Inspection is cheap, but not free for multimodal bundles: the engine also reads the vision encoder's sections (hundreds of MB, briefly in memory). Readings are cached per file version, so the loadModel() that follows doesn't repeat the work.

ModelInfo

Everything a bundle declares about itself. inspectModel() returns it, and so do llm.getModelInfo(), useModel().modelInfo and the embedding equivalents for the loaded bundle.

The capability facts come from the bundle itself, never from its file name.

recommendBackend(info, options?)

function recommendBackend( info: ModelInfo, options?: RecommendBackendOptions, ): BackendRecommendation interface BackendRecommendation { /** The backend to load with */ backend: Backend; /** Every usable backend for this bundle on this device, best first */ candidates: Backend[]; /** False when the bundle targets hardware this device lacks (e.g. another SoC's NPU) */ compatible: boolean; /** Why — log it, or show it in a model picker */ reason: string; } interface RecommendBackendOptions { /** 'speed' (default) follows the bundle's own preference order; * 'compatibility' puts CPU first whenever the bundle allows it. */ prefer?: "speed" | "compatibility"; /** The device to evaluate (default: this one) */ device?: DeviceInfo; }

Picks the backend for a bundle on this device: the bundle's own preference order (info.backends.text), minus what this device can't run — no GPU driver, an NPU build for another SoC, NPU on iOS. A bundle that declares nothing gets CPU.

typescript
const { backend, compatible, reason } = recommendBackend(await inspectModel(path));
if (!compatible) showError(reason);
await llm.loadModel(path, { backend });
From /core

The main entry point evaluates this device by default. The copy in react-native-litert-lm/core has no device to read: without options.device, it assumes a GPU is present and skips SoC-specific NPU builds.

The load pre-flight

loadModel() inspects the bundle before any weights load, and acts on what it declares:

  • The wrong kind of bundle rejects with MODEL_TYPE_MISMATCH: an embedding model in createLLM(), or an LLM in createEmbedder().
  • A bundle that needs a newer engine rejects with RUNTIME_TOO_OLD: its minRuntimeVersion is compared with LITERT_LM_VERSION, the engine this package ships ("0.18.0").
  • With backend omitted, the bundle's preferred backend that this device can run is used (CPU when the bundle declares none). A per-SoC NPU build on another phone rejects with UNSUPPORTED.
  • Image and audio encoders load only if the bundle has them, on the backends it declares; multimodal: false keeps an engine text-only.
  • maxContextTokens above the bundle's maximum is clamped, so the memory estimate and the engine agree.
  • enableSpeculativeDecoding on a bundle without a drafter loads without it.

It notes what it changed with console.warn — a backend it picked, a context you set that was clamped, a flag it dropped. Then the memory pre-flight runs on the adjusted config. A bundle whose metadata can't be read (an older bundle) skips this step with a warning and the engine has the final say; a missing file still rejects with MODEL_NOT_FOUND. llm.getModelInfo() and useModel().modelInfo return what the loaded bundle declared.

The checks are pure functions you can run yourself — in a model picker, or in Node through react-native-litert-lm/core:

function preflightLoad( info: ModelInfo, config: LLMConfig | undefined, options?: PreflightOptions, ): PreflightResult function preflightEmbedder( info: ModelInfo, config: EmbedderConfig | undefined, options?: Omit<PreflightOptions, "expectType">, ): EmbedderPreflightResult interface PreflightOptions { device?: DeviceInfo; /** The model type the caller is loading (default 'llm') */ expectType?: "llm" | "embedding"; /** Runtime to check minRuntimeVersion against (default: this package's engine) */ runtimeVersion?: string; } /** EmbedderPreflightResult has the same shape, with an EmbedderConfig. */ interface PreflightResult { /** The config to load with: backend chosen, context clamped */ config: LLMConfig; /** Whether config differs from the caller's */ changed: boolean; /** Adjustments that were made, worth logging */ notes: string[]; }

ModelRegistry

ModelRegistry is the single source of truth for model storage: it coordinates URL sniffing, HTTPS enforcement, atomic downloads with progress, and cache queries. createLLM's loadModel and the useModel hook both route through it — use it directly for pre-download UIs, cache management, and storage-usage screens.

isCached

isCached(pathOrUrl: string): boolean

Check if a model file is cached locally. Accepts a filename, local path, or HTTPS URL. Returns true if cached and the file has size > 0.

getFilePath

getFilePath(pathOrUrl: string): string

Get the absolute local path of a cached model. Accepts a filename, local path, or HTTPS URL.

listCachedFiles

listCachedFiles(): ModelFile[]

List all locally cached model files. Returns an array of ModelFile descriptors containing path, size, and modification time.

deleteFile

deleteFile(pathOrUrl: string): void

Delete a cached model file. Accepts a filename, local path, or HTTPS URL.

getFileSizeBytes

getFileSizeBytes(absolutePath: string): number

Size in bytes of a file at an absolute path (not restricted to the cache). Returns -1 if the file does not exist.

resolveModel

async resolveModel(pathOrUrl: string, options?: ModelDownloadOptions): Promise<string>

Resolve a model path or URL. Sniffs the protocol: an HTTPS URL is downloaded to the native cache directory (with throttled progress callbacks) if not already cached; a local path is returned directly. Resolves to the absolute local path of the model. A failed download rejects with a LiteRTLMError with code DOWNLOAD_FAILED, keeping the native error as cause.

typescript
export interface ModelDownloadOptions {
  headers?: Record<string, string>;
  onProgress?: (progress: number) => void;
}

URL handling

  • A leading file:// prefix is stripped.
  • The cache filename is derived from the URL's last path segment, with the query string stripped.
  • When no filename can be derived, resolution throws Invalid model URL: <url> (code INVALID_INPUT).
HTTPS only

http:// URLs are rejected — a LiteRTLMError with code INVALID_INPUT and the message Insecure HTTP URLs are not allowed for model downloads. Use HTTPS instead: <https-url>

ModelFile

typescript
export interface ModelFile {
  fileName: string;
  absolutePath: string;
  sizeBytes: number;
  lastModifiedMs: number;
}
Note

ModelFile is the return type of listCachedFiles(). It is currently not re-exported from the package root, so infer it from the return value rather than importing it by name.

Example: manage the cache

typescript
import { ModelRegistry, GEMMA_4_E2B_IT } from "react-native-litert-lm";

// 1. Check the cache before showing a download prompt
if (!ModelRegistry.isCached(GEMMA_4_E2B_IT)) {
  // 2. Download with progress (no-op if already cached)
  await ModelRegistry.resolveModel(GEMMA_4_E2B_IT, {
    onProgress: (p) => setProgress(Math.round(p * 100)),
  });
}

// 3. Absolute local path — pass to loadModel(), show in a storage UI, …
const path = ModelRegistry.getFilePath(GEMMA_4_E2B_IT);
console.log(path, ModelRegistry.getFileSizeBytes(path));

// 4. Free the multi-GB file when the user removes the model
ModelRegistry.deleteFile(GEMMA_4_E2B_IT);

Deprecated instance methods deprecated

The instance-level downloadModel(url, fileName, onProgress?) and deleteModel(fileName) methods are deprecated — ModelRegistry supersedes both. They remain callable, but new code should use ModelRegistry.resolveModel and ModelRegistry.deleteFile instead.
