Core API

Configuration

Every knob the engine exposes: the session-level LLMConfig, the per-message ExecuteOptions, backend selection, and the full iOS vs Android support matrix.

LLMConfig

The session-level configuration, passed to loadModel() or as the second argument to useModel(). All fields are optional.

FieldTypeDefaultDescription
systemPrompt string — System prompt prepended to the conversation to guide model responses.
backend Backend 'cpu' Primary compute backend for text generation. Falls back automatically if unavailable. The vision encoder is always GPU (required by Gemma models); the audio encoder is always CPU.
maxContextTokens number 4096 Total engine KV-cache budget in tokens (prompt + history + output combined). Must be ≥ total input tokens + desired output tokens. For compiled bundles, should not exceed the bundle's compiled cache_length.
maxOutputTokens number 1024 Maximum tokens generated per response. For compiled bundles, must not exceed the compiled decode-chunk size. Applies on both platforms (LiteRT-LM 0.15+); override per message via ExecuteOptions.maxOutputTokens.
maxTokens deprecated number 1024 Use maxContextTokens and maxOutputTokens instead. When set alone (without the new fields), maps to both for backward compatibility.
temperature number 0.7 Sampling temperature (0.0 = deterministic, 1.0 = creative).
topK number 40 Top-K sampling (number of top tokens to consider).
topP number 0.95 Top-P (nucleus) sampling threshold.
multimodal boolean filename sniffing Whether this is a multimodal model. When enabled, the engine handles image/audio tokens properly. If not specified, the system falls back to filename sniffing ("3n"/"gemma3").
tools ToolDefinition[] — List of tools/functions the model can call.
enableSpeculativeDecoding boolean false Enable speculative decoding (multi-token prediction) if the model supports it.
enableStructuredOutput boolean false Initialize the constraint provider (LLGuidance) so structured output can be requested per message via ExecuteOptions.responseSchema/responseRegex (LiteRT-LM 0.15+). Adds a small one-time initialization cost at conversation creation.
thinking ThinkingOptions engine default Session-default thinking/reasoning controls (Gemma 4, LiteRT-LM 0.15+). Override per message via ExecuteOptions.thinking.
numThreads iOS number — CPU threads for text generation (CPU backend). Lower values reduce peak memory-bandwidth pressure at some speed cost. iOS only — the Android Kotlin SDK does not expose thread control.
prefillChunkSize iOS number — Prefill chunk size (CPU backend only). Smaller chunks reduce peak activation memory during long-prompt prefill at some latency cost.
activationDataType iOS ActivationDataType — Activation tensor data type; 'f16' roughly halves activation memory vs 'f32'.
loraPath string — Path to a LoRA adapter weights file applied on top of the base model.
audioLoraPath string — Path to an audio LoRA adapter weights file.
loraRank iOS number — LoRA rank of the adapter (must match training). iOS only — Android derives the rank internally.
streamToolCalls boolean false Stream tool-call tokens through the token callback as they are generated (LiteRT-LM v0.14+). Content arrives wrapped in channel markers; use executeWithEvents() for typed events. Token-level streaming is iOS only; completed tool calls surface as typed events on both platforms.
toolCallChannelName string "tool_call" Channel name used to delimit streamed tool-call tokens.
forceLoad boolean false Skip the automatic pre-flight memory check in loadModel() and load even when the estimate says the model likely does not fit. JS-side only — the native engine ignores this field.
Context is the memory lever

maxContextTokens is the biggest memory lever: it sizes the KV cache the engine allocates for the conversation. It must be at least your total input tokens plus the output tokens you want, and for compiled bundles it should not exceed the bundle's compiled cache_length (just as maxOutputTokens must not exceed the compiled decode-chunk size).

ExecuteOptions

Per-message options for execute() and executeWithEvents() (LiteRT-LM v0.14+). These apply to a single response, overriding session defaults where noted.

FieldTypeDefaultDescription
maxOutputTokens number — Cap output tokens for this message only, overriding session-level maxOutputTokens. Both platforms (LiteRT-LM 0.15+).
visualTokenBudget iOS number — Visual token budget for this message (multimodal models). Lower values reduce memory spent encoding images.
responseSchema string — Constrain this response to match a JSON Schema (constrained decoding via LLGuidance, LiteRT-LM 0.15+). Pass the schema as a JSON string; the engine guarantees the output parses against it. Requires enableStructuredOutput: true at load time. Takes precedence over responseRegex. For best schema adherence use low-temperature sampling (temperature: 0) in the load config.
responseRegex string — Constrain this response to match a regular expression (LLGuidance, LiteRT-LM 0.15+). Requires enableStructuredOutput: true. Ignored when responseSchema is also set.
repetitionPenalty number — Multiplicative repetition penalty (HuggingFace style). 1.0 = no penalty; values clamped to ≥ 1.0 by the engine. Applies only to tokens generated in this response.
presencePenalty number 0 Subtractive presence penalty (OpenAI style): subtracted from a token's logit once it has appeared in the generated window. Positive values discourage repetition.
frequencyPenalty number 0 Subtractive frequency penalty (OpenAI style): subtracted per prior occurrence of the token in the generated window.
penaltyWindowSize number 0 How many recent generated tokens the penalties consider. 0 = the entire generation history.
noRepeatNgramSize number — Ban exact n-gram repeats of this size during generation (0 disables). Useful against looping output.
noRepeatNgramWindowSize number 0 Window of recent tokens checked for repeating n-grams. 0 = entire generation history.
suppressTokens iOS number[] — Token IDs that must never be generated — logits forced to -inf. iOS only; ignored with a warning on Android (see below).
thinking ThinkingOptions LLMConfig.thinking Thinking/reasoning override for this message.
suppressTokens on Android

suppressTokens is ignored (with a warning) on Android: LiteRT-LM 0.15.0's SuppressTokensConfig JNI binding looks up a Kotlin-mangled internal accessor and aborts the process, so the library refuses to use it there until upstream fixes the mismatch.

ThinkingOptions

Thinking/reasoning generation controls (Gemma 4 models, LiteRT-LM 0.15+). Set in LLMConfig.thinking as the session default, or per message via ExecuteOptions.thinking. 

interface ThinkingOptions {
  enabled?: boolean;
  tokenBudget?: number;
}
FieldTypeDefaultDescription
enabled boolean true (engine default) Whether thinking/reasoning generation is enabled.
tokenBudget number -1 Token budget for reasoning generation. -1 means unlimited. Lower budgets reduce latency and memory at some quality cost on reasoning-heavy prompts.

Backend

type Backend = "cpu" | "gpu" | "npu";
  • 'cpu' — CPU inference (slowest, always available).
  • 'gpu' — GPU acceleration (fast, recommended for most devices).
  • 'npu' — NPU/Neural Engine (fastest on supported hardware). Requires compatible hardware (e.g., Qualcomm Hexagon, MediaTek APU); if NPU is unavailable, LiteRT-LM automatically falls back to GPU.

The backend applies to text generation only: the vision encoder is always GPU (required by Gemma models), and the audio encoder is always CPU.

getRecommendedBackend()

function getRecommendedBackend(): Backend

Returns 'cpu' as the safe default — always. GPU (Metal on iOS, GPU delegate on Android) is faster but may not be available on all devices or model configurations.

checkBackendSupport(backend)

function checkBackendSupport(backend: Backend): string | undefined

Checks whether a backend configuration is supported on the current platform. Returns a warning message if the configuration may have issues, or undefined if OK.

PlatformBackendResult
iOS / Android'cpu'undefined
iOS'gpu'undefined (iOS always supports GPU via Metal)
Android'gpu'"GPU backend requires OpenCL support, which is unavailable on most Samsung and Qualcomm devices. Will automatically fall back to CPU if unavailable."
iOS'npu'"NPU (Neural Engine) is not yet supported on iOS. Mapped to GPU (Metal) internally."
Android'npu'"NPU backend requires compatible hardware (Qualcomm Hexagon, MediaTek APU, etc.). Will automatically fall back to CPU if unavailable."

checkMultimodalSupport()

function checkMultimodalSupport(): string | undefined

Checks whether multimodal features (image/audio) are supported on the current platform — currently always returns undefined: both iOS and Android ship the vision/audio executor ops, so there is no platform-level block. Whether a given call succeeds depends on the loaded model: only multimodal models (e.g. Gemma 3n) bundle the vision/audio executors. Pass multimodal: true to loadModel for such models, or rely on filename sniffing ("3n"/"gemma3").

ActivationDataType

type ActivationDataType = "f32" | "f16" | "i16" | "i8";

Activation tensor data types (memory/precision trade-off). Set via LLMConfig.activationDataType iOS — 'f16' roughly halves activation memory vs 'f32'.

Works everywhere

Structured output (responseSchema/responseRegex), penalties (repetitionPenalty, presencePenalty, frequencyPenalty, penaltyWindowSize), n-gram bans, and thinking overrides work on both platforms (LiteRT-LM 0.15+).

Android GPU (OpenCL)

Android GPU requires the device to ship libOpenCL.so, which varies by vendor and SoC rather than by brand — present on a Galaxy S22 / Snapdragon 8 Gen 1, absent on plenty of other devices. Probe it with checkBackendSupport('gpu') before committing to the GPU backend; the engine auto-falls back to CPU either way. NPU likewise auto-falls back when the hardware (Qualcomm Hexagon, MediaTek APU) is not present.

iOS: models over ~2 GB

Add the Extended Virtual Addressing entitlement for models over ~2 GB — without it, iOS caps virtual memory at ~2 GB and Jetsam kills the app during load. See Getting started → iOS entitlement for large models.
