Core API

Configuration

Every knob the engine exposes: the session-level LLMConfig, the per-message ExecuteOptions, backend selection, and the full iOS vs Android support matrix.

LLMConfig

The session-level configuration, passed to loadModel() or as the second argument to useModel(). All fields are optional. loadModel() checks it against the bundle first, filling in an omitted backend and clamping maxContextTokens — see the load pre-flight.

FieldTypeDefaultDescription
systemPrompt string — System prompt prepended to the conversation to guide model responses.
backend Backend the bundle's preference Primary compute backend for text generation. Omitted: the bundle's preferred backend that this device can run, else CPU — see Default backend. Falls back to CPU automatically if the requested backend fails to start. Image and audio encoders follow the bundle (see multimodal).
maxContextTokens number 4096 Total engine KV-cache budget in tokens (prompt + history + output combined). Must be ≥ total input tokens + desired output tokens. A value above the bundle's declared maximum is clamped to it, so the memory estimate and the engine agree.
maxOutputTokens number 1024 Maximum tokens generated per response. For compiled bundles, must not exceed the compiled decode-chunk size. Applies on both platforms (LiteRT-LM 0.15+); override per message via ExecuteOptions.maxOutputTokens.
maxTokens deprecated number 1024 Use maxContextTokens and maxOutputTokens instead. When set alone (without the new fields), maps to both for backward compatibility. Warns once; removed in 1.0.
temperature number 0.7 Sampling temperature (0.0 = deterministic, 1.0 = creative).
topK number 40 Top-K sampling (number of top tokens to consider).
topP number 0.95 Top-P (nucleus) sampling threshold.
multimodal boolean from the bundle Unset: every encoder the bundle has (image, audio) loads, on the backend the bundle declares. false keeps the engine text-only; true on a bundle without encoders loads text-only, with a warning. Only for a bundle whose metadata can't be read does the old file-name guess ("3n"/"gemma3") apply — deprecated, and it warns once.
tools ToolDefinition[] — Tools the model can call. Calls come back as <tool_call> markers in the response (parseToolCalls() reads them); your app runs the tool and answers with toolResultPart() — see Tool calling.
enableSpeculativeDecoding boolean false Speculative decoding (multi-token prediction), if the bundle has a drafter. The session default; createConversation({ speculativeDecoding }) overrides it per conversation. A bundle without a drafter loads without it, with a warning — see Speculative decoding.
chatTemplate string the bundle's A Jinja chat template that replaces the bundle's own — the fix for a community bundle whose template is missing or wrong. The engine adds the BOS token itself, so the template must not. An invalid template fails the load — see Chat templates.
enableStructuredOutput boolean false Initialize the constraint provider (LLGuidance) so structured output can be requested per message via ExecuteOptions.responseSchema/responseRegex (LiteRT-LM 0.15+). Adds a small one-time initialization cost at conversation creation.
thinking ThinkingOptions engine default Session-default thinking/reasoning controls (Gemma 4, LiteRT-LM 0.15+). Override per message via ExecuteOptions.thinking.
numThreads number — CPU threads for text generation (CPU backend). Lower values reduce peak memory-bandwidth pressure at some speed cost. Both platforms (Android since LiteRT-LM 0.18's Backend.CPU(threadCount)).
maxVisionTokensPerImage number — Cap on the visual tokens one image may use, set when the engine loads (Gemma 4: 70, 140, 280, 560 or 1120; inspectModel() lists a bundle's options). Lower caps cut image memory and latency; ExecuteOptions.visualTokenBudget picks a budget per message, up to this cap. Both platforms.
gpu.metalResidencySet iOS boolean false Keep model weights resident in GPU memory with a Metal residency set (iOS 18+), so they aren't paged between calls. Ignored on older iOS and by non-GPU backends. Set as gpu: { metalResidencySet: true }.
singleThreadedExecution iOS boolean false Run the engine on a single thread — for debugging and reproducibility, not speed. The Android Kotlin SDK does not expose it.
prefillChunkSize iOS number — Prefill chunk size (CPU backend only). Smaller chunks reduce peak activation memory during long-prompt prefill at some latency cost.
activationDataType ActivationDataType — Activation tensor data type; 'f16' roughly halves activation memory vs 'f32'. Mainly a GPU setting — GPU backends default to 'f16'; on CPU the engine picks its own kernels and, for quantized bundles such as Gemma 4 E2B, generates identically whatever the value. A type the model and backend cannot run fails the load. Both platforms.
loraPath string — Path to a LoRA adapter weights file applied on top of the base model.
audioLoraPath string — Path to an audio LoRA adapter weights file.
loraRank iOS number — LoRA rank of the adapter (must match training). iOS only — Android derives the rank internally.
streamToolCalls boolean false Stream tool-call tokens through the token callback as they are generated (LiteRT-LM v0.14+). Content arrives wrapped in channel markers; use executeWithEvents() for typed events. Token-level streaming is iOS only; completed tool calls surface as typed events on both platforms.
toolCallChannelName string "tool_call" Channel name used to delimit streamed tool-call tokens.
forceLoad boolean false Skip the automatic pre-flight memory check in loadModel() and load even when the estimate says the model likely does not fit. JS-side only — the native engine ignores this field.
Context is the memory lever

maxContextTokens is the biggest memory lever: it sizes the KV cache the engine allocates for the conversation. It must be at least your total input tokens plus the output tokens you want, and for compiled bundles it should not exceed the bundle's compiled cache_length (just as maxOutputTokens must not exceed the compiled decode-chunk size). When a bundle declares its maximum, loadModel() clamps a larger value to it before the memory estimate.

ExecuteOptions

Per-message options for execute() and executeWithEvents() (LiteRT-LM v0.14+). These apply to a single response, overriding session defaults where noted.

FieldTypeDefaultDescription
maxOutputTokens number — Cap output tokens for this message only, overriding session-level maxOutputTokens. Both platforms (LiteRT-LM 0.15+).
visualTokenBudget number — Visual token budget for images in this message (Gemma 4: 70, 140, 280, 560 or 1120), up to LLMConfig.maxVisionTokensPerImage. Lower values reduce memory and time spent encoding images. Both platforms; on Android the SDK's budget is process-wide, so messages that set it run one at a time.
responseSchema string — Constrain this response to match a JSON Schema (constrained decoding via LLGuidance, LiteRT-LM 0.15+). Pass the schema as a JSON string; the engine guarantees the output parses against it. Requires enableStructuredOutput: true at load time. Takes precedence over responseRegex. For best schema adherence use low-temperature sampling (temperature: 0) in the load config.
responseRegex string — Constrain this response to match a regular expression (LLGuidance, LiteRT-LM 0.15+). Requires enableStructuredOutput: true. Ignored when responseSchema is also set.
repetitionPenalty number — Multiplicative repetition penalty (HuggingFace style). 1.0 = no penalty; values clamped to ≥ 1.0 by the engine. Applies only to tokens generated in this response.
presencePenalty number 0 Subtractive presence penalty (OpenAI style): subtracted from a token's logit once it has appeared in the generated window. Positive values discourage repetition.
frequencyPenalty number 0 Subtractive frequency penalty (OpenAI style): subtracted per prior occurrence of the token in the generated window.
penaltyWindowSize number 0 How many recent generated tokens the penalties consider. 0 = the entire generation history.
noRepeatNgramSize number — Ban exact n-gram repeats of this size during generation (0 disables). Useful against looping output.
noRepeatNgramWindowSize number 0 Window of recent tokens checked for repeating n-grams. 0 = entire generation history.
suppressTokens number[] — Token IDs that must never be generated in this response — logits forced to -inf. Both platforms (Android since LiteRT-LM 0.17.0, which fixed the JNI binding that aborted the process through 0.16.1).
thinking ThinkingOptions LLMConfig.thinking Thinking/reasoning override for this message.

ThinkingOptions

Thinking/reasoning generation controls (Gemma 4 models, LiteRT-LM 0.15+). Set in LLMConfig.thinking as the session default, or per message via ExecuteOptions.thinking. 

interface ThinkingOptions {
  enabled?: boolean;
  tokenBudget?: number;
}
FieldTypeDefaultDescription
enabled boolean true (engine default) Whether thinking/reasoning generation is enabled.
tokenBudget number -1 Token budget for reasoning generation. -1 means unlimited. Lower budgets reduce latency and memory at some quality cost on reasoning-heavy prompts.

Backend

type Backend = "cpu" | "gpu" | "npu";
  • 'cpu' — CPU inference (slowest, always available).
  • 'gpu' — GPU acceleration: Metal on iOS, the OpenCL delegate on Android where the device ships libOpenCL.so.
  • 'npu' — NPU (fastest on supported hardware). Requires compatible hardware (e.g., Qualcomm Hexagon, MediaTek APU), and a per-SoC NPU build runs only on the SoC it was compiled for. iOS has no NPU backend.

If the requested backend fails to start, the engine falls back to CPU. The backend applies to text generation: image and audio encoders load only if the bundle has them, on the backends it declares, and multimodal: false keeps an engine text-only.

Default backend

With backend omitted, loadModel() uses the bundle's preferred backend that this device can run, and CPU when the bundle declares none. A bundle that only runs on hardware this device lacks — a per-SoC NPU build on another phone — rejects with UNSUPPORTED. Set backend to keep a fixed choice. The same logic is available as recommendBackend(), which also explains its pick:

typescript
import { inspectModel, recommendBackend } from "react-native-litert-lm";

const rec = recommendBackend(await inspectModel(path));
rec.backend;    // what loadModel() picks when backend is omitted
rec.candidates; // every backend this device can run for the bundle, best first
rec.reason;     // why, including any backends it skipped

Deprecated helpers deprecated

getRecommendedBackend(), checkBackendSupport() and checkMultimodalSupport() guessed from the platform alone. Use recommendBackend(await inspectModel(path)) and getDeviceInfo(), which know the bundle and the device.

Deprecated in 0.8.0

The three helpers below still work and keep their old results, but each warns once and they are removed in 1.0. setDeprecationWarningsEnabled(false) silences the warnings.

getRecommendedBackend() deprecated

function getRecommendedBackend(): Backend

Returns 'cpu' as the safe default — always. Use recommendBackend(await inspectModel(path)), which knows what the bundle supports and what this device can run; loadModel() already does this when backend is omitted.

checkBackendSupport(backend) deprecated

function checkBackendSupport(backend: Backend): string | undefined

Returns a warning message if the backend may have issues on the current platform, or undefined if OK — judged from the platform alone. Use recommendBackend(info), whose candidates, compatible and reason account for the bundle and this device's GPU driver and SoC, or getDeviceInfo().gpuAvailable for the GPU driver alone.

PlatformBackendResult
iOS / Android'cpu'undefined
iOS'gpu'undefined (iOS always supports GPU via Metal)
Android'gpu'"GPU backend requires OpenCL support, which is unavailable on most Samsung and Qualcomm devices. Will automatically fall back to CPU if unavailable."
iOS'npu'"NPU (Neural Engine) is not yet supported on iOS. Mapped to GPU (Metal) internally."
Android'npu'"NPU backend requires compatible hardware (Qualcomm Hexagon, MediaTek APU, etc.). Will automatically fall back to CPU if unavailable."

checkMultimodalSupport() deprecated

function checkMultimodalSupport(): string | undefined

Always returned undefined: both iOS and Android ship the vision/audio executor ops, so there is no platform-level block. Whether images and audio work depends on the bundle — use (await inspectModel(path)).modalities, which reports what it actually accepts.

ActivationDataType

type ActivationDataType = "f32" | "f16" | "i16" | "i8";

Activation tensor data types (memory/precision trade-off). Set via LLMConfig.activationDataType on both platforms — 'f16' roughly halves activation memory vs 'f32'. It is mainly a GPU setting: GPU backends default to 'f16', and a type the model and backend cannot run fails the load.

Works everywhere

Structured output (responseSchema/responseRegex), penalties (repetitionPenalty, presencePenalty, frequencyPenalty, penaltyWindowSize), n-gram bans, and thinking overrides work on both platforms (LiteRT-LM 0.15+). So, as of 0.8.0, do suppressTokens, visualTokenBudget, numThreads and activationDataType, which Android used to ignore or refuse.

Android GPU (OpenCL)

Android GPU requires the device to ship libOpenCL.so, which varies by vendor and SoC rather than by brand — present on a Galaxy S22 / Snapdragon 8 Gen 1, absent on plenty of other devices. getDeviceInfo().gpuAvailable reports whether this device has one, and loadModel() skips GPU without it when you leave backend unset; the engine auto-falls back to CPU either way. NPU likewise falls back to CPU when the hardware (Qualcomm Hexagon, MediaTek APU) is not present.

typescript
import { getDeviceInfo } from "react-native-litert-lm";

const { gpuAvailable } = getDeviceInfo();
await llm.loadModel(path, { backend: gpuAvailable ? "gpu" : "cpu" });

iOS: models over ~2 GB

Add the Extended Virtual Addressing entitlement for models over ~2 GB — without it, iOS caps virtual memory at ~2 GB and Jetsam kills the app during load. See Getting started → iOS entitlement for large models.
