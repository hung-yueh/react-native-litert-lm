Core API

Inference & streaming

One entry point — execute() — handles text, images, and audio, streaming or blocking. executeWithEvents() adds typed token / toolCall / thinking events on top.

execute()

execute() is the single deep entry point for inference. It replaces all modality-specific send methods: pass an array of MultimodalParts mixing text, image, and audio.

execute( parts: MultimodalPart[], onToken?: (token: string, done: boolean) => void, options?: ExecuteOptions, ): Promise<string>

When onToken is provided, tokens stream incrementally through the callback as they are generated; the promise still resolves with the complete response at the end. Without onToken, the call blocks and resolves with the full response string.

typescript
// Streaming: tokens arrive as they are generated
const full = await llm.execute(
  [{ type: "text", text: "Write a haiku about RAM." }],
  (token, done) => {
    if (!done) appendToUI(token);
  },
);

// Blocking: omit the callback, await the whole response
const reply = await llm.execute(
  [{ type: "text", text: "What is the capital of France?" }],
);
Note

On a createLLM() instance, execute() and executeWithEvents() strip a leading file:// prefix from part paths, so URIs from image pickers work as-is.

MultimodalPart

export interface MultimodalPart { /** The part type: 'text', 'image', or 'audio' */ type: PartType; /** The plain text content, if type is 'text' */ text?: string; /** * Local filesystem path to an image or audio file, if type is 'image' or 'audio'. * Takes precedence over `imageBuffer`/`audioBuffer` if both are set. */ path?: string; /** Raw image binary data, if type is 'image' (zero-copy ArrayBuffer mapping) */ imageBuffer?: ArrayBuffer; /** Raw audio binary data, if type is 'audio' (zero-copy ArrayBuffer mapping) */ audioBuffer?: ArrayBuffer; }
FieldTypeMeaning
type"text" | "image" | "audio"The part type.
textstringPlain text content, if type is 'text'.
pathstringLocal filesystem path to an image or audio file. Takes precedence over imageBuffer/audioBuffer if both are set. A leading file:// is stripped.
imageBufferArrayBufferRaw image binary data (zero-copy ArrayBuffer mapping), if type is 'image'.
audioBufferArrayBufferRaw audio binary data (zero-copy ArrayBuffer mapping), if type is 'audio'.

Buffers are staged to temp files for the engine's file-based API and cleaned up after inference. Image paths are auto-scaled to 1024px on both platforms.

Multimodal example

Send an image as a zero-copy ArrayBuffer alongside text:

typescript
const buf = await (await fetch(Image.resolveAssetSource(require("./photo.jpg")).uri)).arrayBuffer();

const reply = await llm.execute([
  { type: "image", imageBuffer: buf },
  { type: "text", text: "Describe this image." },
]);

executeWithEvents()

The typed-event variant of execute(). Instead of a raw token stream, the callback receives StreamEvents classified as plain response text, tool-call content, or reasoning.

executeWithEvents( parts: MultimodalPart[], onEvent: StreamEventCallback, options?: ExecuteOptions, ): Promise<string>
/** Kind of streamed content. */ export type StreamEventType = "token" | "toolCall" | "thinking"; /** A typed streaming event. */ export interface StreamEvent { /** What this chunk is: plain response text, tool-call content, or reasoning */ type: StreamEventType; /** The text content of this chunk */ text: string; /** True exactly once, on the final event of the stream */ done: boolean; } /** Callback receiving typed streaming events from `executeWithEvents`. */ export type StreamEventCallback = (event: StreamEvent) => void;
typescript
await llm.loadModel(modelUrl, { tools }); // + streamToolCalls: true for token-level streaming on iOS

await llm.executeWithEvents([{ type: "text", text: "Weather in Tokyo?" }], (event) => {
  switch (event.type) {
    case "token":    ui.appendText(event.text); break;
    case "toolCall": toolBuffer += event.text; break;
    case "thinking": ui.showReasoning(event.text); break;
  }
  if (event.done) runTool(JSON.parse(toolBuffer));
});
Note

Completed tool calls surface as toolCall events on both platforms. Setting streamToolCalls: true in the load config additionally streams tool-call and reasoning tokens as they are generated — iOS only; on Android a tool call surfaces once it is complete. The final event of every stream is { type: "token", text: "", done: true }.

Tool calling

Declare tools in LLMConfig.tools at load time. When the model decides to call one, the JSON call content arrives as toolCall events.

export interface ToolDefinition { /** Name of the function/tool */ name: string; /** Human-readable description of what the function/tool does */ description: string; /** JSON schema defining parameter names and types (stringified) */ parametersJson: string; }
typescript
const tools = [
  {
    name: "get_weather",
    description: "Get the current weather for a city",
    parametersJson: JSON.stringify({
      type: "object",
      properties: { city: { type: "string" } },
      required: ["city"],
    }),
  },
];

await llm.loadModel(modelUrl, { tools });

let toolBuffer = "";
await llm.executeWithEvents([{ type: "text", text: "Weather in Tokyo?" }], (event) => {
  if (event.type === "toolCall") toolBuffer += event.text;
  if (event.done && toolBuffer) {
    const call = JSON.parse(toolBuffer); // shape follows the model's tool-call JSON
    dispatchTool(call);
  }
});

Thinking

Gemma 4 models (LiteRT-LM 0.15+) can reason before answering. Set a session default via LLMConfig.thinking, and override per message via ExecuteOptions.thinking. Reasoning content arrives as thinking events from executeWithEvents().

export interface ThinkingOptions { /** * Whether thinking/reasoning generation is enabled. * @default true (engine default) */ enabled?: boolean; /** * Token budget for reasoning generation. `-1` means unlimited. * Lower budgets reduce latency and memory at some quality cost on * reasoning-heavy prompts. * @default -1 */ tokenBudget?: number; }
typescript
// Session default at load time
await llm.loadModel(modelUrl, { thinking: { enabled: true, tokenBudget: 512 } });

// Per-message override
await llm.execute(parts, onToken, {
  thinking: { enabled: false }, // skip reasoning for this message
});

Structured output

Constrain a response to a JSON Schema or a regular expression (constrained decoding via LLGuidance, LiteRT-LM 0.15+). Set enableStructuredOutput: true at load time, then pass responseSchema or responseRegex per message. When a schema is used, the engine guarantees the output parses against it.

typescript
const llm = createLLM();
await llm.loadModel(GEMMA_4_E2B_IT, {
  enableStructuredOutput: true,
  temperature: 0, // greedy sampling improves schema adherence
});

const json = await llm.execute(
  [{ type: 'text', text: 'Extract: "Ada Lovelace, born 1815, London"' }],
  undefined,
  {
    responseSchema: JSON.stringify({
      type: 'object',
      properties: { name: { type: 'string' }, birthYear: { type: 'number' }, city: { type: 'string' } },
      required: ['name', 'birthYear', 'city'],
    }),
  },
);
const person = JSON.parse(json); // guaranteed to parse

// Or a regex constraint:
await llm.execute([{ type: 'text', text: 'Pick a priority.' }], undefined, {
  responseRegex: 'P[0-3]',
});
Requires enableStructuredOutput

Using responseSchema or responseRegex without enableStructuredOutput: true in the load config rejects with a clear error. responseSchema takes precedence when both are set. For best schema adherence, use temperature: 0.

Generation controls

Per-message sampling controls fight repetitive or looping output and cap generation length:

typescript
await llm.execute(parts, onToken, {
  maxOutputTokens: 256,            // per-message output cap
  thinking: { enabled: true, tokenBudget: 512 }, // reasoning budget (Gemma 4)
  repetitionPenalty: 1.2,          // ≥ 1.0, HuggingFace-style multiplicative
  presencePenalty: 0.5,            // OpenAI-style subtractive
  frequencyPenalty: 0.3,
  noRepeatNgramSize: 3,            // ban exact 3-gram repeats
  suppressTokens: [128010],        // token IDs forced to -inf (iOS only)
});
OptionDefaultMeaning / platform notes
repetitionPenalty—Multiplicative repetition penalty (HuggingFace style). 1.0 = no penalty; values clamped to ≥ 1.0 by the engine. Applies only to tokens generated in this response.
presencePenalty0Subtractive presence penalty (OpenAI style): subtracted from a token's logit once it has appeared in the generated window.
frequencyPenalty0Subtractive frequency penalty (OpenAI style): subtracted per prior occurrence of the token in the generated window.
penaltyWindowSize0How many recent generated tokens the penalties consider. 0 = the entire generation history.
noRepeatNgramSize—Ban exact n-gram repeats of this size during generation (0 disables).
noRepeatNgramWindowSize0Window of recent tokens checked for repeating n-grams. 0 = entire generation history.
suppressTokens—Token IDs that must never be generated — logits forced to -inf. iOS only; ignored with a warning on Android (LiteRT-LM 0.15.0's SuppressTokensConfig JNI binding aborts the process, so the library refuses to use it there until upstream fixes it).
maxOutputTokens—Cap output tokens for this message only, overriding the session-level maxOutputTokens. Both platforms (LiteRT-LM 0.15+).
visualTokenBudget—Visual token budget for this message (multimodal models). Lower values reduce memory spent encoding images. iOS only.

See Configuration for the full ExecuteOptions reference.

Stream parser (advanced)

executeWithEvents() is built on a pure, incremental parser that splits the raw token stream into typed events by channel markers. Use it directly to parse a stream you obtained some other way, or override the markers via createLLM({ streamChannels }).

/** A channel definition: content between `start` and `end` gets `type`. */ export interface StreamChannel { type: Exclude<StreamEventType, "token">; start: string; end: string; } /** Default channel markers (override via `createLLM({ streamChannels })`). */ export const DEFAULT_CHANNELS: StreamChannel[] = [ { type: "toolCall", start: "<tool_call>", end: "</tool_call>" }, { type: "thinking", start: "<thinking>", end: "</thinking>" }, ]; export interface StreamEventParser { /** * Feed a raw chunk; returns zero or more complete events. * Text that could be the start of a channel marker is held back until * disambiguated by the next chunk (or by `finish()`). */ push(chunk: string): StreamEvent[]; /** * Flush any held-back text and emit the final `done` event. * An unterminated channel is flushed as content of that channel. */ finish(): StreamEvent[]; } /** Create an incremental stream-event parser. */ export function createStreamEventParser( channels: StreamChannel[] = DEFAULT_CHANNELS, ): StreamEventParser

Feed push() chunks as they arrive — markers split across chunk boundaries are handled by buffering the longest possible marker prefix. Call finish() at the end of the stream: it flushes any held-back text, and an unterminated channel is flushed as that channel's content. The final event is always { type: "token", text: "", done: true }.

countTokens()

countTokens(text: string): number

Count tokens in a text string. Returns -1 if unavailable.

getContextTokenCount()

getContextTokenCount(): number

Number of tokens currently held in the conversation KV cache (prompt + history + generated tokens). Returns -1 if unavailable. Combine with maxContextTokens to warn before the context window (and its memory) runs out — see getMemoryForecast() on the Memory & errors page. Exact on iOS; approximated on Android, where the SDK doesn't expose tokenizer counts.

getHistory()

getHistory(): Message[]

Get the current conversation history as an array of { role, content } messages.

resetConversation()

resetConversation(historyJson?: string, systemPrompt?: string): void

Clear the conversation context and start fresh. Optionally seed the fresh context from a prior transcript (a JSON array of {role: 'user'|'model', content: string} turns, re-prefilled by the engine on the next message) and/or override the session systemPrompt for the new conversation.
