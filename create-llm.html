Core API

createLLM & instances

createLLM() is the imperative entry point: it returns an engine instance with pre-flight bundle and memory checks, forecasting, budget monitoring, typed event streaming, and multi-conversation support.

createLLM(options?)

export function createLLM(options?: CreateLLMOptions): LiteRTLMInstance

Creates a new LiteRT-LM inference engine instance with memory controls: automatic pre-flight estimation in loadModel (rejects with MemoryError when the model likely doesn't fit), context/KV forecasting, budget monitoring, and typed event streaming. Use it outside React — background tasks, services, or your own state management. Inside components, prefer useModel, which wraps this factory and manages the lifecycle for you.

typescript
import { createLLM } from "react-native-litert-lm";

const llm = createLLM();
await llm.loadModel("https://example.com/model.litertlm", { backend: "gpu" });
const reply = await llm.execute([{ type: "text", text: "What is the capital of France?" }]);
llm.unload(); // free the engine; llm stays reusable

CreateLLMOptions

OptionTypeDefaultMeaning
enableMemoryTracking boolean false Enable automatic memory tracking; a snapshot is recorded after each inference, load, unload, and reset.
maxMemorySnapshots number 256 Maximum number of memory snapshots to retain (ring buffer).
memoryBudget MemoryBudget & { onBudgetExceeded? } — Budget thresholds evaluated on every recorded snapshot. onBudgetExceeded(level) fires on level transitions (ok→warn, warn→critical, …). See Memory & errors.
streamChannels StreamChannel[] DEFAULT_CHANNELS Channel markers for typed event streaming (tool calls, thinking). Defaults to <tool_call>…</tool_call> and <thinking>…</thinking>.

LiteRTLMInstance

The instance is the native LiteRTLM hybrid object plus a set of JS-side augmentations:

loadModel

loadModel: ( pathOrUrl: string, config?: LLMConfig, download?: ((progress: number) => void) | ModelDownloadOptions, ) => Promise<void>

The augmented three-argument replacement for the native loadModel(modelPath, config?). It resolves the URL via ModelRegistry.resolveModel — HTTPS URLs are downloaded to the native cache with progress reported through the callback (0–1); pass the options of ModelRegistry.resolveModel() instead (onProgress, headers, sha256) to send headers or check the file — then checks the bundle and the memory budget before touching the engine:

  1. Bundle pre-flight. It reads the bundle's metadata and refuses the wrong model type (MODEL_TYPE_MISMATCH), a bundle that needs a newer engine (RUNTIME_TOO_OLD), or one this device can't run (UNSUPPORTED). It fills an omitted backend from the bundle and clamps maxContextTokens to the bundle's maximum — see the load pre-flight.
  2. Memory pre-flight. It estimates weights, KV cache and overhead against the memory the OS reports as available — see Memory & errors.

Native failures reject with a typed LiteRTLMError; an engine out-of-memory has code OUT_OF_MEMORY and, when the pre-flight estimate can be computed, arrives as a MemoryError carrying it.

Warning

On a 'critical' verdict, loadModel throws MemoryError instead of loading: Refusing to load model (<N> MB): <recommendation> Pass { forceLoad: true } to override. Set forceLoad: true in the config to skip the check. See Memory & errors for the estimate math.

getModelInfo

getModelInfo: () => ModelInfo | null

What the loaded bundle declares about itself — type, modalities, context limit, backends, sampler defaults, thinking and tool support — read during loadModel(). Returns null before a load, or when the bundle's metadata could not be read. The fields are documented under ModelInfo; useModel() exposes the same object as modelInfo.

typescript
await llm.loadModel(GEMMA_4_E2B_IT);

const info = llm.getModelInfo();
info?.modalities.vision;          // show the image picker?
info?.maxContextTokens;           // the bundle's context limit
info?.llm?.supportsFunctionCalling;

estimateMemory

estimateMemory: (modelPath?: string, config?: LLMConfig) => MemoryEstimate | null

Pre-flight memory estimate for the most recently loaded (or a given) model path. Returns null if the model file cannot be found.

getMemoryForecast

getMemoryForecast: () => MemoryForecast | null

Forecast context-window / KV-cache growth for the active conversation. Returns null if no model is loaded. Watch nearingLimit to warn before the context runs out.

executeWithEvents

executeWithEvents: ( parts: MultimodalPart[], onEvent: StreamEventCallback, options?: ExecuteOptions, ) => Promise<string>

Execute inference receiving typed streaming events (token / toolCall / thinking) instead of a raw token stream. Completed tool calls arrive as toolCall events on both platforms; streamToolCalls: true in the load config additionally streams tool-call and reasoning tokens as they are generated — iOS only. Full coverage in Inference & streaming.

createConversation

createConversation: (options?: ConversationOptions) => ConversationHandle

Create a logical conversation sharing the loaded engine, with its own systemPrompt and speculativeDecoding overrides — see Multiple conversations below.

resetConversation

resetConversation( historyJson?: string, systemPrompt?: string, speculativeDecoding?: boolean, ): void

Clear the conversation context and start fresh — the native primitive behind createConversation()'s switching. All three arguments are optional:

  • historyJson seeds the new conversation with a prior transcript: the JSON of the Message[] that getHistory() returns. Tool exchanges replay as the model's tool calls and 'tool' results, and the engine re-prefills the transcript on the next message.
  • systemPrompt overrides the session-level system prompt for the new conversation; unset keeps the session default.
  • speculativeDecoding turns speculative decoding on or off for the new conversation; unset follows the session default. true loads the bundle's drafter on first use if the engine started without it.
typescript
// Save a chat, then restore it later (tool calls and results included)
const saved = JSON.stringify(llm.getHistory());
// …
llm.resetConversation(saved);

getHistory() shows the new transcript at once, and messages sent afterwards run in the new conversation. A message sent before the reset that is still generating or waiting to run is cancelled: its promise rejects with INFERENCE_CANCELLED. If the new conversation can't be created, a typed LiteRTLMError says why: thrown by the reset on Android, and by the next message on iOS, where the reset returns before the engine does the work. A manual reset returns the live context to the default conversation. For several chats over one engine, prefer createConversation(), which does this bookkeeping for you, per-conversation speculativeDecoding included.

unload vs close

Note

unload() frees the engine and all its memory but keeps the instance reusable — call loadModel() again to reload. It also clears the cached model path, size, config, and conversation state. close() permanently invalidates the instance; create a new one with createLLM() afterwards.

Neither waits for a message still generating: both cancel it (its promise rejects with INFERENCE_CANCELLED) and report not-ready at once. close() returns immediately and frees the engine in the background; a model loaded afterwards, on any instance, waits for that, so two models never sit in memory together.

Multiple conversations, one engine

createConversation() gives you multiple logical conversations over a single loaded engine — no second model load required.

typescript
const support = llm.createConversation({ systemPrompt: 'You are a support agent.' });
const summarizer = llm.createConversation({ systemPrompt: 'You summarize tersely.' });

await support.execute([{ type: 'text', text: 'My app crashes on launch.' }]);
await summarizer.execute([{ type: 'text', text: 'Summarize: …' }]); // context switch
await support.execute([{ type: 'text', text: 'It happens on iOS 18.' }]); // remembers the crash report

support.getHistory();     // this conversation's transcript
await summarizer.release(); // drop a side-chain when done

ConversationOptions

export interface ConversationOptions { /** Override the session-level `systemPrompt` for this conversation. */ systemPrompt?: string; /** * Turn speculative decoding (the bundle's multi-token drafter, e.g. Gemma 4's * MTP) on or off for this conversation; unset follows * `LLMConfig.enableSpeculativeDecoding`. `true` loads the drafter on first use. */ speculativeDecoding?: boolean; }

A bundle without a drafter ignores speculativeDecoding: true with a warning. See Speculative decoding for when it pays off.

typescript
const drafting = llm.createConversation({ speculativeDecoding: true });
const plain = llm.createConversation({ speculativeDecoding: false });

ConversationHandle

export interface ConversationHandle { /** Stable identifier for this conversation. */ readonly id: string; /** Run inference in this conversation (switches native context if needed). */ execute( parts: MultimodalPart[], onToken?: TokenCallback, options?: ExecuteOptions, ): Promise<string>; /** Typed-event variant of {@link execute}. */ executeWithEvents( parts: MultimodalPart[], onEvent: StreamEventCallback, options?: ExecuteOptions, ): Promise<string>; /** This conversation's transcript (live when active, snapshot otherwise). */ getHistory(): Message[]; /** Drop this conversation's transcript; further calls on the handle reject. */ release(): Promise<void>; }

Behavior

  • One engine holds one native context at a time. Switching between conversations replays the target's transcript into a fresh context via resetConversation.
  • The replay means a re-prefill cost on the next message — expect seconds of extra latency on long transcripts.
  • Multimodal turns replay as text placeholders ([Image], [Audio]); images and audio are not re-encoded on switch.
  • Tool exchanges replay too — the model's tool calls and the 'tool' results — so a restored conversation still knows what the tools returned. See Tool calling.
  • Once createConversation() has been called, all inference — including top-level execute() — serializes through one queue.
  • Calls on a released handle throw: LiteRTLM: conversation '<id>' has been released. Conversation ids follow the pattern conversation_<n>.
  • Calling resetConversation() manually on the instance clears the live context and returns ownership to the default conversation.

Deprecated send methods deprecated

The sendMessage* family and sendMultimodalMessage are deprecated in favor of execute() / executeWithEvents() — one entry point for text, images, audio and tool results, with per-message ExecuteOptions. They still work (each routes through execute() internally), warn once per method, and are removed in 1.0. setDeprecationWarningsEnabled(false) silences the warnings.

DeprecatedReplacement
sendMessage(text)execute([{ type: "text", text }])
sendMessageAsync(text, onToken)execute([{ type: "text", text }], onToken)
sendMessageWithImage(text, path)execute([{ type: "text", text }, { type: "image", path }])
sendMessageWithImageAsync(text, path, onToken)execute([{ type: "text", text }, { type: "image", path }], onToken)
sendMessageWithAudio(text, path)execute([{ type: "text", text }, { type: "audio", path }])
sendMessageWithAudioAsync(text, path, onToken)execute([{ type: "text", text }, { type: "audio", path }], onToken)
sendMultimodalMessage(parts)execute(parts)
Note

The *Async variants resolve Promise<void> — collect the response from the token callback, not the returned promise. execute() resolves with the full response either way.
