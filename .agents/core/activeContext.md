## Executive Summary
Integrate the Laya Multilingual LiteRT model family (`litert-community/Laya-Multilingual-LiteRT`), supporting on-device System-1 decision making in 100+ languages with under 60ms latency via LiteRT `CompiledModel` on Android (GPU with explicit FP32 precision and CPU fallback) and Nitro Modules bindings. Supports the three canonical decision types: `choice` (categorical selection), `score` (ordinal evaluation), and `bool`/`noul` (binary hypothesis verification).

## Architecture Overview
- **Nitro Spec**: `src/specs/LayaModel.nitro.ts` defining the `LayaModel` HybridObject.
- **Android Native Runtime**: `HybridLayaModel.kt` orchestrating the two LiteRT compiled graphs:
  1. Main encoder graph (`laya_ml_s256_embeds_wfp16.tflite`): processes gathered embeddings, attention mask, and question type one-hot tensor.
  2. Action head graph (`laya_ml_act_head_fp32.tflite`): receives pooled CLS embedding and raw uncalibrated distribution features.
  - Native helper components in `android/.../litertlm/laya/`:
    - `LayaEmbeddings.kt`: memory-maps the 393.2 MB `token_embeddings_fp16.bin` table and converts rows from float16 to float32.
    - `LayaTokenizer.kt`: pure Kotlin BPE tokenizer matching the 256,000 token vocabulary.
    - `LayaPromptBuilder.kt`: builds sequence tokens and records marker indices.
    - `LayaDecoder.kt`: applies calibration temperature, executes stable softmax, and formats outputs.
    - `LayaCalibration.kt`: parses and provides option-bucket calibration temperatures.
- **iOS Native Stub**: `HybridLayaModel.swift` satisfying `HybridLayaModelSpec`.
- **TypeScript Layer**: `src/layaModel.ts` implementing `createLayaModel()`, high-level methods `decideChoice()`, `decideScore()`, `decideBool()`, and `decide()`.
- **Public Entry Point**: Exported via `src/index.ts`.

## Critical Implementation Details
1. **Host-Side Embedding Gather**: The model takes embedding rows rather than token IDs. The 393.2 MB float16 table is memory-mapped, and tokens are converted to float32 without heap duplication. Padded tokens use the table's actual PAD row (id 0).
2. **Two-Stage Execution**:
   - Main graph runs first, returning `token_logits [1, N]` and `pooled_cls [1, 768]`.
   - Feature vector `feats [1, 4]` is computed from raw uncalibrated marker logits (`[top1, top1 - top2, entropy, k / 255.0]`).
   - Action head runs with `pooled_cls` and `feats`, producing `act_logits [1, 2]`.
3. **Calibrated Softmax**: Option logits are scaled by `temperature_by_options` or default question type temperature from `laya_ml_calibration.json` before softmax.

## Known Risks & Mitigations
- GPU incompatibility: Fall back to CPU gracefully when GPU accelerator initialization fails.
- Memory: Use memory mapping for the token table to avoid duplicating 393 MB in JVM heap.
