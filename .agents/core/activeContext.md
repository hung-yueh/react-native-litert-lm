## Executive Summary
Add support for Kev-0.8B (and Kev-4B), Google LiteRT-based System-1 decision models (`litert-community/Kev-0.8B-LiteRT`). Provides high-speed reactive decision making (under 50ms) via Nitro Modules and Kotlin `CompiledModel` on Android with GPU support, pair graph shared-state caching, and rich TypeScript APIs for `choice`, `noul` (yes/no), and `score` questions.

## Architecture Overview
- **Nitro Spec**: `src/specs/KevModel.nitro.ts` defining `KevModel` HybridObject.
- **Android Native**: `HybridKevModel.kt` wrapping `KevRowGraph` (`serving_default`) and `KevPairGraph` (`state_prefill` + `question_step`) using LiteRT CompiledModel and GPU accelerator.
- **iOS Native**: `HybridKevModel.swift` satisfying `HybridKevModelSpec`.
- **TypeScript Layer**: `src/kevModel.ts` implementing delimiters (PAD 248044, OPTION_START 248049, OPTION_END 248050, STATE 248060, QUESTION 248061, DECIDE 248062), prompt rendering, pointer head projection ($z_k = ((h_k W_k^T + b_k) \cdot (h_{dec} W_q^T + b_q)) / 16 / T$), softmax, and typed response formatting.
- **Public Entry Point**: Exported via `src/index.ts` with `createKevModel()`.

## Tech Stack for This Feature

## Critical Implementation Details
1. **Delimiter Tokens & Escaping**: All input texts must have `<|name|>` rewritten to `<¦name¦>` to avoid accidental delimiter injection.
2. **Buffer Sharing & Optimization**: In `KevPairGraph`, state output buffers are passed directly as input buffers to `question_step` to prevent extra data copies through the JVM/app.
3. **Pointer Head Math**: Readout vectors for `decide` and `optionEnds` are projected with $W_k, b_k, W_q, b_q$ and scaled by temperature $T=2.3510958125672174$.

## Known Risks & Mitigations
- GPU incompatibility on some devices: Fall back to CPU gracefully when GPU accelerator initialization fails.
- Large state token sequences exceeding pair graph $L_s$: Automatically route to a larger pair graph or row graph.
